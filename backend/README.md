# Экосистема колледжа — рабочий прототип

Веб-приложение: мессенджер (личные и групповые чаты), истории (24 часа),
лента новостей, профиль с уровнем и опытом (XP), задания от преподавателей
и админ-панель. Интерфейс — тёмная тема с тёплым янтарным акцентом,
собранная по референсу дизайна, который прислал заказчик.

## Как запустить

Нужен установленный Node.js (18+).

```bash
npm install
npm start
```

Откройте в браузере: **http://localhost:3000**

При первом запуске автоматически создаётся администратор:

- Логин: `admin`
- Пароль: `admin123`

Все данные хранятся в файле `data.json` (создаётся автоматически рядом с
`server.js`). Для прототипа это заменяет полноценную БД — при переходе к
продакшену стоит перенести на PostgreSQL/MySQL, добавить это можно позже
без переделки фронтенда, поменяется только `db.js`.

## Роли и сценарий использования

1. **Администратор** (`admin/admin123`):
   - создаёт группы (учебные потоки/классы) — вкладка «Админ-панель»;
   - создаёт аккаунты преподавателей;
   - видит и может удалять пользователей.
   - При создании группы автоматически создаётся групповой чат этой группы.

2. **Преподаватель** (создаётся администратором):
   - логинится по выданным логину/паролю;
   - во вкладке «Задания» создаёт задания для конкретной группы,
     указывает награду в XP и (опционально) дедлайн;
   - открывает задание и видит список ответов студентов, ставит оценку
     и вручную подтверждает начисление XP;
   - может публиковать в общую ленту колледжа.

3. **Студент** (регистрируется сам, выбирая свою группу):
   - видит общий чат колледжа и чат своей группы;
   - видит задания своей группы, открывает и отправляет решение текстом;
   - во вкладке «Профиль» видит уровень, шкалу опыта, био и группу.

Опыт (XP) начисляется преподавателем при проверке ответа. Уровень
считается автоматически (100 XP = 1 уровень).

**Важно:** мессенджер (личные чаты, групповые чаты, поиск пользователей,
истории) не привязан к ролям — любой пользователь, независимо от роли,
может написать любому другому, создать группу или опубликовать историю.
Ограничение по ролям есть только там, где это осмысленно с точки зрения
учебного процесса: публикация в общую ленту (преподаватель/админ) и
создание заданий (преподаватель/админ).

## Мессенджер: личные чаты, группы, история переписки

- **Начать личный чат**: кнопка «+» на вкладке «Чаты» → «Личное сообщение» →
  поиск по имени или логину → клик по человеку сразу открывает чат
  (или переиспользует уже существующий, если он был раньше).
- **Создать групповой чат**: та же кнопка «+» → «Групповой чат» → задать
  название → добавить участников через поиск (можно несколько) →
  «Создать группу». Это отдельная сущность от учебных групп (классов)
  администратора — обычный групповой чат, как в Telegram, доступен
  всем ролям.
- **Поиск и фильтры**: строка поиска фильтрует список чатов по названию,
  вкладки «Все / Личные / Группы» переключают отображаемые типы.
- **Непрочитанные**: у каждого чата отдельно для каждого участника
  хранится отметка "последний раз читал в...". Бейдж с количеством
  непрочитанных сообщений обновляется во время автообновления (раз в
  3 секунды, как и раньше для сообщений).

## Истории (24 часа)

- Полоса историй сверху вкладки «Чаты»: своя история первой (с кнопкой
  «+» поверх аватара, чтобы добавить фото/видео), затем чужие — сначала
  непросмотренные (яркое кольцо), затем просмотренные (серое кольцо).
- Публикация: фото/видео + необязательная подпись. Открывается
  полноэкранный просмотр с прогресс-барами (как в Instagram): картинка
  показывается 5 секунд, видео — 8 секунд (для прототипа фиксированная
  длительность, не привязана к реальной длине видео), можно листать
  вперёд/назад или закрыть в любой момент.
- Автор может удалить свою историю раньше срока — кнопка «Удалить» в
  просмотрщике.
- **Истории автоматически исчезают через 24 часа** — сервер проверяет
  срок годности при каждом обращении к `/api/stories` и удаляет
  просроченные записи вместе с файлами на диске.

## Лента новостей и посты профиля

- **Общая лента** (вкладка «Лента») видна всем, но публиковать в неё
  могут только **преподаватели и администратор** — форма создания поста
  скрыта от студентов, и сервер дополнительно перепроверяет роль на
  бэкенде, так что подделать запрос из консоли браузера не получится.
- Пост может содержать текст, фото или видео (jpg/png/gif/webp,
  mp4/webm/mov, до ~15 МБ на клиенте / 20 МБ на сервере — для прототипа
  файлы передаются как base64 в JSON и сохраняются в
  `public/uploads/posts/`).
- **Любой пользователь** (студент, преподаватель, админ) может добавлять
  фото/видео/текстовые посты **в свой собственный профиль** — это
  отдельная лента, видимая при открытии профиля (своего или чужого),
  и в общую ленту колледжа она не попадает. У преподавателя/админа при
  публикации в профиль есть отдельная галочка «Также опубликовать в
  общую ленту», если пост должен быть виден всем.
- Клик по имени автора поста в общей ленте открывает всплывающее окно
  с профилем этого человека и его публикациями.
- Автор поста (и администратор) может удалить свой пост — вместе с
  публикацией удаляется и файл на диске.
- Лайки реализованы просто (переключатель like/unlike на пользователя),
  без уведомлений — этого достаточно для прототипа.

## Профиль: био и «участник с ...»

- На вкладке «Профиль» можно задать короткое описание о себе (до 300
  символов) — иконка карандаша рядом с текущим био.
- Пилюля «С {год} года» считается от даты регистрации аккаунта
  (`createdAt`), для старых аккаунтов при миграции проставляется
  текущая дата первого запуска после обновления.

## Про защиту от копирования — важно понимать честно

Технически **ни один браузер и ни один сайт не может запретить скриншот**,
сделанный средствами операционной системы, сторонней программой или второй
камерой. Это фундаментальное ограничение веба, а не недоработка. Любой
сервис, который заявляет о "защите от скриншотов", на деле либо не
работает против системного Print Screen / Snipping Tool, либо использует
её как маркетинговый термин для более скромного набора мер.

В прототипе реализован реалистичный набор **сдерживающих мер**
(файл `public/js/protect.js`), которые применяются к тексту задания в
момент его открытия:

1. Отключено выделение текста (`user-select: none`) и контекстное меню.
2. `Ctrl+C` / `Ctrl+X` / `Ctrl+P` / `Ctrl+S` внутри блока задания
   перехватываются и блокируются, показывается предупреждение.
3. Если скопировать всё же получится (например, через специальные
   расширения браузера), в буфер обмена вместо текста задания
   подставляется предупреждающая надпись.
4. На тексте задания рисуется полупрозрачный водяной знак с именем
   студента и временем открытия — если он всё же сфотографирует экран
   или обойдёт защиту, на снимке останется, кто и когда это сделал.
5. При потере фокуса окна (например, попытка переключиться в программу
   для скриншотов) или нажатии `PrintScreen` контент на короткое время
   размывается, событие можно залогировать на сервере (сейчас это можно
   добавить одной новой ручкой API).

Что это ДАЁТ: отбивает 95% случаев обычного копипаста в нейросеть или
пересылки текстом, а через водяной знак — прослеживаемость при утечке
скриншотов.

Что это НЕ даёт: не остановит человека, который просто сфотографирует
экран на телефон или использует системный снимок экрана — от этого
защититься программно невозможно в принципе, ни в одном веб-приложении
в мире.

## Структура проекта

```
college-ecosystem/
├── server.js          — API-сервер (Express)
├── db.js               — простое JSON-хранилище (замена БД для прототипа)
├── data.json            — файл с данными (создаётся автоматически)
├── backups/              — резервные копии data.json (создаётся автоматически,
│                            ЛЕЖИТ ВНЕ /public — не раздаётся напрямую по URL)
├── public/
│   ├── index.html        — разметка SPA
│   ├── css/style.css      — стили (тёмная тема, янтарный акцент)
│   ├── uploads/posts/      — фото/видео из постов (создаётся автоматически)
│   ├── uploads/stories/     — фото/видео из историй (создаётся автоматически)
│   └── js/
│       ├── app.js          — вся логика интерфейса
│       └── protect.js       — модуль защиты от копирования
```

## Что нового в этом обновлении (профили, сообщения, бэкапы, достижения)

- **Просмотр чужого профиля кем угодно**: на вкладке «Профиль» теперь
  есть поиск «Найти профиль другого человека» — вводите имя или логин,
  открывается тот же просмотрщик профиля, что и раньше при клике на
  автора поста. Работает у всех ролей, включая студентов. Строки в
  «Рейтинге» тоже теперь кликабельны и ведут на профиль.
- **Удаление и пересылка сообщений в чатах**: наведите на сообщение —
  появятся значки «↪ переслать» (у любого сообщения) и «🗑 удалить» (у
  своих). Пересылка открывает список ваших чатов для выбора адресата,
  в пересланном сообщении видно «↪ Переслано от …».
- **Резервные копии — отдельная вкладка** (видна только админу,
  ссылка есть и в самой админ-панели):
  - настраиваемый интервал автоматического бэкапа в днях (по
    умолчанию 7) — сервер проверяет расписание раз в час и сам решает,
    когда пора делать копию;
  - ручное создание копии и скачивание текущей базы одной кнопкой;
  - загрузка файла резервной копии для восстановления — заменяет
    текущие данные, но сначала автоматически сохраняет копию текущего
    состояния «на всякий случай»;
  - список всех копий с размером, датой, скачиванием и удалением.
  - Важно: перезапуск сервера **не требуется** — сервер каждый раз
    читает `data.json` заново, так что восстановленные данные
    подхватываются сразу же. Перезапуск (если вы его всё равно
    сделаете) тоже прочитает файл правильно — ничего не сломается.
- **Достижения**: на вкладке «Профиль» — сетка из 11 бейджей
  (выполненные задания, 100% за тест, найденные AR-точки, уровень,
  публикации, первая покупка в магазине) с прогресс-баром к каждому.
  Статус считается на лету по реальным данным, а не хранится отдельно,
  поэтому не может «разъехаться» с фактическим прогрессом.
- **У студентов выполненные задания больше не мешаются под ногами**:
  вкладка «Задания» разделена на «Активные» / «Выполненные» — по
  умолчанию видно только то, что ещё предстоит сделать.

## Что нового в предыдущем обновлении (онлайн-статус, чаты, роли, статистика)

- **Статус «в сети»**: зелёная точка на аватаре в личных чатах и
  отметка «В сети» / «Не в сети» в профиле пользователя. Статус
  считается по последней активности (запросу к серверу) — если
  человек не показывал активности дольше минуты, он офлайн. Заодно
  это же поле «последняя активность» используется для статистики.
- **Закрепить / удалить чат**: кнопка «⋮» на каждом чате в списке —
  закреплённые чаты показываются вверху списка (с 📌), «удалить»
  скрывает чат только из вашего списка (у собеседника он остаётся);
  если вам снова напишут в этот чат, он сам появится обратно.
- **Выдача прав администратора**: в админ-панели у каждого пользователя
  теперь выпадающий список с ролью — можно повысить любого студента
  или преподавателя до администратора (и понизить обратно), прямо на
  лету, без пересоздания аккаунта. Менять свою собственную роль нельзя
  (чтобы админ случайно не остался без доступа).
- **Рейтинг** (новая вкладка, доступна всем): топ-20 студентов по
  уровню/опыту и топ-20 по количеству выполненных заданий, с
  подсветкой вашей строчки, если вы в списке.
- **Статистика для администратора** (наверху админ-панели): сколько
  людей сейчас в сети, сколько посещений сегодня, график посещений за
  7 дней, количество студентов/преподавателей/админов/групп, а также
  общие цифры по контенту (заданий, постов, заказов в магазине,
  найденных AR-точек).

## Что нового в предыдущем обновлении (мессенджер + настройки + AR)

- **Фото/видео в чатах**: кнопка-скрепка рядом с полем ввода, превью
  перед отправкой, медиа отображается прямо в переписке. В списке
  чатов сообщение без текста показывается как «📷 Фото» / «🎥 Видео».

- **Вкладка «Настройки»** (доступна всем ролям, значения хранятся в
  этом браузере через `localStorage`):
  - размер интерфейса (мелкий/обычный/крупный — масштабирует весь
    интерфейс через CSS `zoom`, работает в Chrome/Edge/Safari; в
    Firefox `zoom` не поддерживается, настройка там не действует);
  - цветовой акцент — 6 цветов на выбор вместо оранжевого по
    умолчанию, применяется мгновенно ко всем кнопкам/акцентам;
  - тема — тёмная (по умолчанию) или светлая, с отдельной палитрой
    цветов, а не просто инверсией;
  - плотность интерфейса (свободно/компактно);
  - автовоспроизведение видео в историях и уменьшение анимаций.
  - Кнопка «Сбросить всё к значениям по умолчанию».

- **Дополненная реальность — первая рабочая версия** (важно понимать
  принцип, чтобы не ждать лишнего): это **не распознавание объектов
  камерой**, а связка **GPS-геолокации** и **наложения интерфейса
  поверх видео с камеры**. Компьютерное зрение (чтобы приложение само
  «узнавало» стенд, статую или картину на видео) — отдельная и
  большая задача, которая потребует внешнего ML-сервиса; в текущем
  вебе-прототипе это не реализовано и не имитируется.

  Как это работает сейчас:
  1. Преподаватель в форме создания задания выбирает тип «Дополненная
     реальность», отмечает точку на встроенной карте (клик по карте
     или кнопка «Использовать моё текущее местоположение»),
     загружает фото места/объекта и пишет комментарий, обязательный
     для прочтения.
  2. Все точки видно на новой вкладке «Карта» (Яндекс.Карты)
     — свои, если ты студент, все свои созданные, если преподаватель,
     и вообще все, если админ. У пройденных точек — зелёная метка.
  3. Студент открывает задание, видит фото/название/описание того,
     что нужно найти, и живое расстояние до точки (через геолокацию
     браузера). Когда он рядом — нажимает «Открыть камеру»: включается
     камера телефона (`getUserMedia`), поверх видео всплывает карточка
     с комментарием преподавателя и кнопкой «Я нашёл это место».
  4. При подтверждении сервер дополнительно перепроверяет координаты
     (если браузер их передал) — если студент физически далеко от
     точки, засчитать её не получится, даже если открыть камеру.
     Награда (XP и золотые монетки) начисляется сразу, как только
     точка засчитана.

  Что не реализовано и потребует отдельной большой задачи в будущем:
  само распознавание объекта в кадре, работа офлайн/в помещениях без
  GPS, и точность позиционирования лучше, чем у обычного GPS телефона
  (~5–15 метров на улице, хуже в помещении) — поэтому радиус
  засчитывания точки сделан с запасом (~100 м).

  - ✅ *Тест* — любое число вопросов, варианты ответов чекбоксами
    (можно отмечать несколько правильных), автоматическая проверка и
    начисление XP сразу после отправки, правильные ответы скрыты от
    студента до прохождения;
  - 📍 *Дополненная реальность* — пока заглушка (недоступна для выбора
    в интерфейсе с пометкой «Скоро»): в будущем обновлении появится
    карта с метками и распознавание точек интереса камерой телефона.
- **Кому назначать задание**: преподаватель выбирает либо целую
  группу, либо конкретных студентов (поиск и мультивыбор).
- **Жалобы на пользователей**: кнопка 🚩 на постах и в профиле любого
  пользователя. Жалобы попадают в новый раздел «Жалобы» в
  админ-панели, где админ может отметить как решённую или удалить.
- **Адаптив под телефоны**: на узких экранах боковая панель скрывается,
  снизу появляется панель с иконками (Лента / Чаты / Задания / Профиль
  / Админ). Список чатов и окно переписки на телефоне показываются по
  одному — с кнопкой «назад». Сетки, модальные окна и карточки
  подстроены под маленький экран.

## Что нового в этом обновлении

- **Исправлена регистрация**: селект группы теперь по умолчанию
  показывает «Выберите группу» вместо примера группы — не выбрать
  ничего не получится, форма это проверяет.
- **Мобильная версия**: добавлена аккуратная кнопка «Выйти» сверху

  в нижней панели больше не выделяется отдельным приподнятым кружком —
  теперь она в одном стиле с остальными.
- **Магазин мерча за золотые монетки**:
  - у каждого пользователя появился счётчик монеток (`coins`),

  - при создании задания преподаватель/админ теперь указывает не
    только награду в XP, но и в монетках — для тестов монетки, как и
    XP, начисляются автоматически пропорционально проценту верных
    ответов, для текстовых заданий преподаватель указывает сумму сам

  - у студентов появилась вкладка «Магазин» со списком товаров,

    же ответе, XP начислялись дважды — теперь при повторной оценке
    старое начисление сначала откатывается.

## Что стоит сделать дальше (уже после дизайна)

- **⚠️ Обязательный шаг перед запуском карты**: карта работает на
  Яндекс.Картах и требует бесплатный API-ключ, иначе вкладка «Карта» и
  выбор точки в задании покажут заглушку вместо карты:
  1. Зарегистрируйтесь на https://developer.tech.yandex.ru/
  2. Создайте ключ для «JavaScript API и HTTP Геокодер» (бесплатный
     тариф для учебного/некоммерческого использования)
  3. Откройте `public/index.html`, найдите строку с
     `YOUR_YANDEX_MAPS_API_KEY` и вставьте туда свой ключ.
  Карта и весь остальной интерфейс (Яндекс.Карты подгружаются с их
  серверов) требуют доступа в интернет на устройстве пользователя — не
  только к самому серверу колледжа. Это единственная функция
  прототипа с таким требованием.

- Перенести хранилище с JSON-файла на настоящую БД (Postgres) — для
  работы с реальной нагрузкой и десятками одновременных пользователей.
- Заменить polling (сообщения и статус чатов раз в 3 сек) на WebSocket
  (socket.io) — чаты и бейджи непрочитанных станут мгновенными, без
  задержки в несколько секунд.
- Заменить base64-в-JSON на настоящую загрузку файлов (multer +
  multipart/form-data) и/или внешнее хранилище (S3) — так фото и видео
  из ленты/историй не будут раздувать `data.json` и оперативную память
  при парсинге больших запросов.
- Добавить пуш/email-уведомления о новых сообщениях, заданиях, оценках
  и постах.
- Реальная длительность видео в просмотрщике историй — сейчас
  используется фиксированный таймер (5с/8с) вместо `video.duration`,
  этого достаточно для прототипа, но не идеально для длинных видео.
- Возможность редактировать состав группового чата после создания
  (сейчас участники задаются только при создании).
- Логирование попыток обхода защиты (PrintScreen, потеря фокуса) на
  сервере — чтобы админ видел, кто и когда пытался скопировать задание.
